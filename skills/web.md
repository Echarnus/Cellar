# Skill: HTML / CSS / JS for the Cellar site

Best practices for the GitHub Pages landing page. Portable guide; Claude's auto-discovered copy is
`.claude/skills/cellar-web/SKILL.md`. Read [`../AGENTS.md`](../AGENTS.md) first. This file is about
the **page**; the generator that emits it has its own guide, [`python.md`](python.md).

## What the site is

A static site generated by [`../Scripts/gen-site.py`](../Scripts/gen-site.py) into `pages/dist/`: the
landing page with the supported-games list (`index.html`), `faq.html`, `404.html`, `sitemap.xml`
and `robots.txt`. It has **no build step and no framework** — the generator emits self-contained
HTML with inline CSS/JS. Never introduce a bundler, npm, or a runtime dependency.

## How it ships

`.github/workflows/pages.yml` owns it end to end:

- **Every PR** that touches `profiles/**`, `app/Resources/AppIcon.png`, the generator, the checker or
  the workflow builds the site, proves both TOML parsers produce the same pages, runs
  `pages/check-site.py --external`, and uploads the pages as the `github-pages` artifact — that
  artifact is the PR's preview.
- **A push to `main`** touching the same paths deploys with `actions/deploy-pages`. Only the deploy
  job holds `pages: write` + `id-token: write`; it runs in the `github-pages` environment, which
  should allow deployments from `main` only (Settings → Environments → github-pages).
- **A finished release** (`workflow_run` of *Release*, tag pushes only) deploys again, so the
  Download button names the new version without anyone touching the site.

The Pages checks are path-filtered, so they are deliberately **not** required status checks: a
required check that never runs would block every PR that doesn't touch the site.

## Rules

- **Every game comes through a store.** Cellar has no store-less or manual-download path, so the
  site never offers or implies one: no "No store" filter, label or copy. A profile without a known
  `store` fails the build, and `check-site.py` fails on copy like "no store" or "manual download".
  Whether the store's *app* must run while playing is a different fact ("While playing").
- **Data-driven, never hand-authored.** The games grid is generated from `profiles/*.toml`, so the
  page can't drift from what Cellar actually supports. To change what a card shows, change the
  generator, not the HTML. Adding a profile updates the site on the next push to `main`.
- **The download button is the point.** The generator asks the GitHub API for the latest release at
  build time and links its `.dmg` directly, preferring the versionless `Cellar.dmg` that
  `make-dmg.sh` now produces (v0.2.0 shipped `Cellar-0.2.0.dmg`, which is why a hard-coded
  `releases/latest/download/Cellar.dmg` 404'd). Without an answer — offline, rate-limited,
  `CELLAR_SITE_OFFLINE=1` — the button opens the releases page instead, which is always right.
- **Edit the generator, then regenerate and look.** `python3 pages/gen-site.py`, then open
  `pages/dist/index.html`. A site change is verified by rendering it, not by reading the Python.
- **Keep `gen-site.py` Python 3.9-safe.** It uses `tomllib` with a hand-rolled fallback parser for
  older Pythons — and 3.9 is what this machine runs, so the fallback is the live local path. Details
  and the cross-parser traps: [`python.md`](python.md) · [`profiles.md`](profiles.md).
- **Escape every interpolated value.** Game names, statuses and URLs all come from profiles and all
  land in HTML — see [`python.md`](python.md) for which interpolations currently skip it.

## HTML/CSS quality bar (Apple-calibre)

- **Semantic HTML:** `header` / `main` / `footer` / `section`, one `<h1>`, real landmarks. Every
  `<img>` gets meaningful `alt`.
- **Theme-aware:** define the full light palette as CSS custom properties on `:root`; redefine only
  the changed tokens under `@media (prefers-color-scheme: dark)`. Never give a colour its only
  definition inside the dark block. Paint an explicit background on `body`.
- **Responsive:** relative units, flexbox/grid, `max-width:100%` on media. The body never scrolls
  horizontally; wide content scrolls inside its own container.
- **Accessible:** visible focus states, **contrast ≥ 4.5:1 for body text and ≥ 3:1 for large text and
  UI components** (WCAG 2.2 AA), respect `@media (prefers-reduced-motion: reduce)` for animations,
  hit targets ≥ 44px. Honour `prefers-contrast: more` if you add a low-contrast decorative treatment.
- **Self-contained:** inline the CSS/JS. External assets only from well-known CDNs, always
  version-pinned; prefer none. Copy local images into `pages/dist/` (the generator copies the app icon to
  `site/icon.png`).
- **Fast:** no blocking third-party scripts; images sized; animations are cheap transforms/opacity.
  Cover art is `loading="lazy"` and degrades to a `.noimg` placeholder via `onerror` — keep that
  fallback, because the Steam CDN is not ours and will occasionally 404.

## Verify — measure it, don't eyeball it

`python3 pages/check-site.py` does the mechanical part and is what CI runs: every relative link,
image and `#anchor` resolves, links into the repo's `main` name files that exist, one `<h1>`, no
skipped heading level, every `<img>` has `alt`, no duplicate ids, every input labelled, every button
typed and named, no leaked `{…}`, and every pair in the generator's `CONTRAST` table meets WCAG 2.2
AA. Change a colour in `LIGHT`/`DARK` and the checker measures it. `--external` adds the outgoing
links (404/410 fail; a network error is reported, not failed).

`python3 pages/gen-site.py` succeeds; `pages/dist/index.html` opens with correct title, working Download
CTA, one card per profile, the app icon present, balanced tags, and no unrendered template markers.
Then actually check the claims:

1. **Contrast:** sample the real foreground/background pairs (browser devtools reports the ratio on
   any text node) in **both** appearances. "Looks fine in dark mode" is how 3.9:1 body text ships.
2. **Keyboard:** tab through the page — every interactive element reachable, focus always visible,
   order matches the visual layout.
3. **Structure:** one `<h1>`, headings not skipping levels, every `<img>` with a real `alt`. A
   markup validator or an automated accessibility pass (axe, Lighthouse) catches these in seconds and
   is worth running whenever the generator's HTML changes shape.
4. **Narrow width and reduced motion:** no horizontal body scroll; animations actually stop.
